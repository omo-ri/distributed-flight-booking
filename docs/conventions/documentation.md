# 文档规范 —— 理由与目录职责

> **规则本身写在根目录 [`CLAUDE.md`](../../CLAUDE.md) § 3，那里是唯一权威。**
>
> 这份文档只回答"为什么这样分类"，并列出每个目录的具体职责。冲突时以 `CLAUDE.md` 为准。
> 变更纪律的通用理由见 [engineering.md](./engineering.md)。

## 1. 为什么按"什么时候需要改它"分类，而不是按主题

按主题分类（"缓存相关的都放一起"）在文档变多之后必然失效，因为一个主题会同时包含"现在是什么"和"将来要做什么"，这两种东西的更新触发条件完全不同 —— 前者跟着代码走，后者跟着计划走。混在一个文件里就会出现"做完一条要在四百行文档里找位置划掉"的窘境，然后就没人划了。

分类轴换成更新触发条件之后，每份文档只有一个改它的理由，也只有一个该改它的时刻。

**几个类别的性质差异值得单独说**：

- **事实层会漂移，而且是渐进的。** 每次只漂一点，半年后整个 `docs/` 就只能当历史读物。所以规则是同一个 PR 内改完，不允许"回头再补"。
- **架构文档里描述一个不存在的组件，比没有文档更有害** —— 读者会按它做决策。
- **记录层"永不修改"是硬规则。** 一份复盘写的是"当时我们以为是 X，后来发现是 Y"，事后回去把它改成"就是 Y"，就毁掉了这份文档全部的价值 —— 它记录的不只是结论，是**认知过程**。同理，压测报告记的是那一次运行在那个环境下的真实数字，改数字等于伪造实验记录。
- **知识层与本仓库解耦**，判据很简单：如果一段内容里出现了 `booking-service` 这类专有名词，它多半不属于那里。

## 2. 目录职责

```
docs/
├── README.md              导航
├── architecture/          系统现在是什么
│   ├── overview.md          运行时拓扑、数据流、边界、关键机制
│   ├── data-model.md        schema 与约束
│   ├── contracts.md         gRPC / REST 契约、错误码映射
│   └── capabilities.md      能力清单，每条指向代码位置
├── conventions/           规则的理由（规则本身在 CLAUDE.md）
│   ├── engineering.md       分支、提交、目录、配置、可观测性、变更纪律
│   └── documentation.md     本文
├── plans/                 要做什么、为什么
│   ├── roadmap.md           分阶段路线图
│   └── gap-analysis.md      对标岗位的能力缺口（G-xx）
├── tasks/                 可执行条目，一条一文件
│   ├── README.md            看板索引
│   ├── D-xx-*.md            已发现的缺陷
│   └── done/                完成后移入
├── knowledge/             按主题的知识笔记
│   ├── kubernetes/ observability/ sre/ linux-network/ datastore/
├── runbooks/              一条告警一个文件
└── reports/               带日期，写完不改
    ├── postmortems/         故障复盘与演练记录
    ├── load/                压测报告
    └── reviews/             周期性 SLO / error budget 评审
```

## 3. 为什么文件名不带 `01-` `02-` 这类序号

全局序号在文档跨目录移动后就失效了，而且插入一份新文档要么破坏序号连续性、要么重命名一片文件（连带所有链接失效）。目录名已经承担了分类和排序，序号是冗余的。

只有两类东西保留稳定 ID：**任务**（要被提交信息 `Refs: D-01` 引用）和 **ADR**（要被互相引用）。ID 一旦分配就不再复用，即使任务被取消 —— 复用会让历史提交里的 `Refs:` 指向另一件事。

## 4. 关于根目录 README

根 `README.md` 是课程交付物（俄语），受众是课程评分者，保持原样不动。它同时是仓库门面，等哪天需要改写时，把俄语版归档到 `docs/archive/`，而不是直接覆盖 —— 它是这个项目的起点记录。

## 5. 引用代码为什么要"行号 + 函数名"

行号一定会过期。给出足够的上下文（函数名 / 变量名），让读者在行号漂移后还能找到目标；只给行号的引用在三次提交之后就变成了误导。

## 6. 给 AI 协作留的接口

任务文件带 YAML frontmatter（`id` / `severity` / `status` / `phase` / `blocks` / `refs`），是为了让"当前阶段有哪些未完成的 critical 任务"这类问题可以被机器回答，而不用通读全部文档。

新增字段前先问：这个字段会被谁读？没有读者的元数据只是维护负担。

AI 协作的行为规则全部收敛在根目录 [`CLAUDE.md`](../../CLAUDE.md)，不在 `docs/` 里另开一份 —— 两份规则必然分叉，而分叉的规则等于没有规则。
